# 釐清問題

用戶迭代修改時若涉及破壞性 Schema 變更（如刪除欄位、改變資料類型），如何處理現有資料？

# 定位

Feature：迭代修改（Section 5）
PRD Section 5.1：「Schema 已更新」

# 決議

**選項 B + D：自動備份 + 嘗試自動轉換，失敗才警告**

處理流程：
1. 偵測到破壞性變更時，先自動備份現有資料
2. 嘗試自動資料轉換：
   - 類型轉換（如 INT → VARCHAR）
   - 欄位重命名映射
   - 預設值填充
3. 轉換成功 → 執行 Migration，保留備份供還原
4. 轉換失敗 → 警告用戶，說明原因，提供選項：
   - 強制執行（資料遺失）
   - 取消變更
   - 手動處理

備份策略：
- 備份保留 7 天
- 用戶可在「版本歷史」中查看並還原

# 影響範圍

- Migration 生成邏輯需加入轉換嘗試
- 備份系統設計
- 用戶確認流程（轉換失敗時）
- 儲存成本（備份空間）
